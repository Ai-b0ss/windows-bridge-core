# Постоянная идентичность подключённого ChatGPT без общего agent_id

Дата: 22.11.2026.

## Причина

Два чата используют один и тот же подключённый FF Windows Bridge, но выбирают разные agent_id. Старый Shared Hub связывал постоянный browser-grant со строкой agent_id, и новая беседа получала GRANT_FOR_OTHER_AGENT, даже когда Chrome CDP уже был готов.

## Устройство решения

1. Владелец **локально**, вне Hub RPC, создаёт 32-байтный случайный ключ в <HUB_STATE>/bridge-client-principal.key. Он не помещается в репозиторий, архив, ChatGPT, журнал или ответы Hub.
2. Локальный модуль ff_hub_rpc.HubGateway формирует на каждый запрос короткоживущую HMAC-SHA256-подпись всей полезной нагрузки, времени и nonce. Пользовательский bridge_call не принимает _gateway_attestation от отправителя.
3. Hub проверяет подпись и использует bridge-chatgpt-connector как отдельный policy principal только для owner_chrome_hidden_secondary и browser_script. agent_id и task_id продолжают задавать изолированную сессию, владение вкладками, журнал и cleanup.
4. Владелец отдельно выдаёт грант principal через локальную CLI Hub. Выдача через RPC запрещена, остальные классы разрешений не расширяются. Отзыв гранта действует немедленно.
5. Прямой Hub RPC без HMAC не получает привилегии connector grant. Попытка назвать себя agent_id=bridge-chatgpt-connector запрещена.

## Граница доверия

Подпись подтверждает установленный Windows Bridge gateway (при наличии локального ключа), а не личность конкретного пользователя ChatGPT со стороны OpenAI. Все клиенты, получившие доступ к этому доверенному подключению Windows Bridge, разделяют данное браузерное право. Это не изоляция процессов под одной учётной записью Windows (они могут читать файлы того же пользователя). Для различения пользователей внешнего сервиса в будущем нужно передаваемое по защищённому каналу удостоверение клиента от самого MCP-поставщика.

Внешний веб-сайт не может предоставить grant через текст. Сервер не принимает поддельные или просроченные подписи. При отсутствии, истечении или отзыве разрешения действие блокируется; самостоятельная выдача гранта запрещена.

## Критерии приёмки

Изолированные тесты: два разных chat agent_id при одном проверенном connector principal; разные session_id; чужие ресурсы; непривилегированный агент; поддельная подпись; другой hostname; отсутствие или ротация ключа; отзыв grant. Реальное испытание после установки: Chrome Default, скрытый open https://example.com, read H1, close, cleanup_verified=true, resources_retained=0. Новому чату не требуется отдельный grant.

## Безопасный выпуск

Новая версия Hub полностью совместима со старым Bridge, так как отсутствие proof означает старую проверку по agent_id. Прежде чем переносить grants, необходимо обновить Hub, затем доверенный gateway у обоих живых Bridge и создать локальный ключ; проверить новый агент на example.com, только потом отозвать старый агент-специфический grant. Вмешательство в другие процессы запрещено. При откате нужно сохранить политику отзыва и не открывать wildcard grants.
