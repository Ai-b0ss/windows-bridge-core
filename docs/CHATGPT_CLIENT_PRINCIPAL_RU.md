# Автономный доступ к FF Windows Bridge

Режим: automatic_hidden_chrome_for_verified_bridge_gateway (22.11.2026).

## Поведение
1. Windows Bridge проверяет входящий вызов существующим авторизованным транспортом.
2. При первом авторизованном Hub-вызове локальный Gateway создаёт случайный 256-битный ключ в state/hub/bridge-client-principal.key. Создание эксклюзивное, без перезаписи уже существующего ключа. Значение не выдаётся агентам.
3. Gateway ставит короткоживущую HMAC-SHA256 подпись под каждый Hub-запрос. Hub проверяет подпись, включая тело запроса, timestamp и nonce. Клиенту нельзя задавать поле _gateway_attestation самостоятельно.
4. Проверенный gateway-принципал bridge-chatgpt-connector автоматически получает только четыре класса Hub: owner_chrome_hidden_secondary, browser_script, read_diagnose и own_resources. Этого достаточно для скрытых вкладок Chrome Default, чтения, заполнения форм, собственных операций и очистки. Запуск процессов, изменение файлов, отправка данных вне браузерного сценария, финансы, секреты, системные настройки и управление видимым рабочим столом НЕ получают автоматического разрешения. Для них остаётся прежняя политика грантов.
5. Неудостоверенный клиент сохраняет старую политику грантов. Выбор строки agent_id не является удостоверением; чужие session_secret не действуют.
6. Каждый чат сохраняет отдельную сессию, вкладки, ресурсы и очистку. Ограничения, явно указанные пользователем в конкретной задаче, обязательны к соблюдению агентом.

## Реальная граница
Подпись удостоверяет локальный FF Windows Bridge gateway, но не конкретный аккаунт ChatGPT. Все клиенты, ранее получившие доступ к этому Bridge, попадают в общую область доверия **только в пределах четырёх классов Hub**. Это не отдельная криптографическая авторизация ChatGPT. Для строгого происхождения именно ChatGPT требуется дополнительное подтверждение от внешнего коннектора, которого сейчас нет. Заголовок Origin, User-Agent и имя agent_id не годятся.

Права Hub не отменяют отдельные ограничения самой платформы ChatGPT, Chrome, Windows, других сервисов или API. Процессы одного пользователя Windows не являются изолированными ОС-доверенными доменами.

## Проверки
Подписанные запросы двух разных agent_id: автоматическое разрешение, независимые вкладки и session_close. Неподписанный прямой клиент, поддельная подпись, зарезервированный agent_id и чужой секрет сессии: отказ. После перезапуска и в новом чате всё должно работать без дополнительных грантов.

Для постоянного отключения доступа требуется отключить доверенное подключение Windows Bridge: удаление ключа само по себе не отзовёт разрешение, так как локальный gateway создаст новый при следующем авторизованном обращении.

## Условия приёмки и пределы гарантии
- Транспорт Cloudflare Worker передаёт в локальный Bridge только op/args; существующая проверка соединения удостоверяет доступ к Bridge, но не конкретный ChatGPT-аккаунт.
- В Hub нельзя отличить отдельные чаты по криптографически проверенному происхождению: agent_id — только метка, session_secret — секрет сессии, локальный HMAC — подпись шлюза.
- Не выдавать доступ посторонним внешним клиентам: сохранять действующую аутентификацию Cloudflare/Bridge. Не принимать Origin/User-Agent/agent_id как доказательство.
- Новые чаты смогут использовать маршрут автоматически только при наличии подключённого Windows Bridge и доступности его инструментов. Установка локального навыка сама по себе не гарантирует активацию плагина в новом чате.
- При блокировке конкретного запроса платформой не повторять операцию через другой интерфейс.
