# Windows Bridge: руководство владельца

Документ для владельца ПК. Описывает, как устроен Bridge, как агент получает доступ к компьютеру, как это включить, выключить, проверить и откатить. Технические детали и решения: [SKILL_FIRST_PERMISSION.md](design/SKILL_FIRST_PERMISSION.md). Пути ниже даны относительно корня установки (`<ROOT>`, у каждого свой).

## 1. Идея в двух слоях

1. **Транспорт (MCP).** Чат (ChatGPT) отправляет вызовы на ваш ПК. Основной путь: Cloudflare Worker MCP. Запасные: GitHub Issues/Actions и Desktop Commander. Все они приходят в один локальный сервер Bridge на `127.0.0.1` (порт 39073 у интерактивного экземпляра).
2. **Скилл.** Агент получает инструкцию (`skills/windows-bridge/SKILL.md`, а также ответ `agent_workflows` при подключении): сначала искать программные пути, потом скрытые, потом спрашивать вас. Мышь и клавиатуру можно использовать только после вашего «да» в чате.

Никакой подписи на каждое действие нет. Доверие выражается вашим сообщением в чате, а защита состоит из ограничений по времени и окну, журнала, уведомления на экране, кнопки «Стоп» и паузы, когда вы сами работаете за компьютером.

## 2. Порядок работы агента

1. Определить устройство и состояние Bridge (`ping`, `capabilities`, `device_info`).
2. Искать программный путь: официальный API/CLI/SDK/MCP/COM, затем **ваш Chrome через расширение Playwright** (без мыши), затем UIA/Win32 без фокуса, затем скрытый рабочий стол (Блокнот, WordPad, Paint, Word, Excel, PowerPoint, Cursor/VS Code).
3. Если пути нет на ПК: искать в интернете (в том числе чужие мосты и переходники), ставить недостающее бесплатно и с проверкой.
4. Только когда пути закончились: спросить вас в чате. Ваш ответ «да» (или заранее «разрешаю на сегодня для задачи …») и есть разрешение.
5. Передать ваши слова в Bridge: `set_desktop_mode` с `owner_chat_permission` (дословная цитата, приложения, срок).
6. Действовать в выданном окне, проверяя результат, затем закрыть за собой.

## 3. Включение и выключение

| Что | Как |
| --- | --- |
| Включить разрешение из чата | создать `<ROOT>/state/chat-permission.json`: `{"schema":"ff-chat-permission-v1","enabled":true,"max_ttl_seconds":7200}` |
| Ограничить включение по времени | добавить `"owner_opt_in_until": <Unix-время UTC>` |
| Выключить | удалить файл или поставить `"enabled": false` (перезапуск не нужен) |
| Максимальный срок одного разрешения | `max_ttl_seconds` (от 60 до 86400, по умолчанию 7200) |

Агент не может включить эту функцию через RPC: файл читается только локально.

## 4. Что вы видите на ПК

- **Уведомление справа внизу**: «Агент … работает на вашем ПК». Появляется один раз за задачу, когда агент впервые реально отправляет ввод, не забирает фокус клавиатуры. Через минуту без действий пишет «Агент закончил» и закрывается.
- **Кнопка «Стоп»**: отзывает доступ. Следующее действие агента получит `OWNER_STOPPED`, режим вернётся в обычный.
- **Пауза**: если вы двигаете мышь или печатаете, агент получает `OWNER_ACTIVE` и ждёт (повторит через пару секунд). Перед самым первым действием вы должны не трогать ввод около 1,5 секунды.

Уведомление работает только в интерактивной сессии Windows. Экземпляр Bridge, запущенный до входа в систему (порт 39076), ничего не показывает и ввод через него невозможен.

## 5. Журналы и отчёт

Файлы в `<ROOT>/state/chat-permission/`:

- `chat-permission.jsonl`: каждое выданное разрешение с дословной цитатой, агентом, задачей, приложениями, сроком;
- `scope-violations.jsonl`: попытки выйти за рамки;
- `route-search.jsonl`: какие задачи делали поиск программных путей.

Каждый журнал при достижении 2 МБ переименовывается в `<имя>.1` (хранится одно предыдущее поколение), так что диск они не заполнят.

Сводка за сутки: операция `scope_report` (аргумент `hours`, по умолчанию 24). Что означают виды:

| Вид | Смысл |
| --- | --- |
| `VISIBLE_INPUT_WITHOUT_PERMISSION` | агент пытался вводить без разрешения; отказ |
| `OUT_OF_SCOPE_APP` | ввод в окно вне разрешённых; отказ до ввода |
| `PERMISSION_EXPIRED` | разрешение истекло |
| `ROUTE_SEARCH_SKIPPED` | разрешение выдано для задачи без поиска программных путей; только запись |

Нулевой отчёт за сутки означает, что скилла достаточно. Если нарушения есть, включайте технические ограничения по одному виду.

Чего Bridge не видит: что приложение отправляет от вашего имени. Это держится только на скилле (отправка людям требует вашего отдельного «да» на точный текст и адресата).

## 6. Ваш Chrome без мыши

Расширение Playwright уже установлено в профилях Chrome. Агент подключается к вашему Chrome с вашими входами, открывает **свою** вкладку, читает страницу деревом доступности и действует по ссылкам `ref` (`attach` → `new_tab` → `find` → `act` → `close`). Мышь, клавиатура и фокус не используются. Клик без заданного условия проверки засчитывается, если страница заметно изменилась; иначе вернётся `ACTION_UNVERIFIED` («пытался, результат неизвестен», нужно посмотреть страницу и не жать повторно). Точная последовательность вызовов: раздел «Owner's Chrome» в `SKILL.md`.

## 7. Windows-MCP

Постоянный рабочий процесс обслуживает вызовы (первый ~11 с, последующие ~1,4 с, останавливается после 3 минут простоя). Инструменты ввода (`Click`, `Type`, `Scroll`, `Move`, `Shortcut`, `Clipboard`, `MultiSelect`, `MultiEdit`, `Wait`) работают только в режиме `dedicated` и только когда окно переднего плана входит в разрешённые цели. `Shell`, `Registry`, `Process` и `App` недоступны по этому пути.

## 8. Обновление и откат

1. Проверить изменения в отдельной копии: `python -m unittest discover -s tests` и `python tests/integration/isolated_rpc_smoke.py` (запускает отдельный Bridge на случайном порту, ваш не трогает).
2. Подождать, пока агент не работает (в `audit.jsonl` нет операций, кроме `ping`, около двух минут): перезапуск обрывает его терминальные сеансы.
3. Скопировать изменяемые файлы в `bridge-v3/backups/<имя>/` и положить `ROLLBACK.txt`.
4. Копировать файлы **точно как в `git show HEAD:путь`** (байты важны, в репозитории окончания строк CRLF).
5. Проверить компиляцию встроенным Python и перезапустить только процесс интерактивного Bridge (завершить процесс, слушающий порт 39073; задача `FF-Bridge-V3-Keeper` запустит его снова за несколько секунд). Супервизор не останавливать.
6. Проверить `ping`, `capabilities`, `chat_permission_status`, `scope_report`.
7. Откат: вернуть файлы из `backups/<имя>/`, удалить новые, перезапустить так же.

## 9. Коды ответов

| Код | Что делать |
| --- | --- |
| `INTERACTIVE_FOREGROUND_DISABLED` | нет режима `dedicated`: сначала `set_desktop_mode` с разрешением |
| `CHAT_PERMISSION_DISABLED` | функция не включена локально: сообщить владельцу, самому не включать |
| `CHAT_PERMISSION_QUOTE_REQUIRED` / `_INVALID` / `_DURATION_INVALID` | неверные поля `owner_chat_permission` |
| `OWNER_ACTIVE` | владелец за компьютером: подождать и повторить |
| `OWNER_STOPPED` | владелец нажал «Стоп»: остановиться, спросить заново |
| `DESKTOP_TARGET_OUTSIDE_SCOPE` | окно не из разрешённых: ничего не введено |
| `DESKTOP_MODE_EXPIRED` | срок вышел: попросить новое «да» |
| `WINDOWS_MCP_ACTION_OUTCOME_UNKNOWN` | действие могло выполниться: посмотреть состояние, не повторять вслепую |
| `ACTION_UNVERIFIED` | то же для браузера: наблюдать, потом решать |
| `STALE_TARGET` | ссылки на элементы устарели: снова `find` |
| `AUTHORITY_IDENTITY_INVALID` | в вызове нет `agent_id`/`task_id` |

## 10. UAC и капча

Окно UAC (запрос прав администратора) обычный ввод не нажимает. Интерактивный экземпляр Bridge запускается с наивысшими правами, поэтому всё, что он сам запускает, уже администраторское и окно UAC обычно не появляется. Если появилось или на странице капча, агент останавливается и пишет вам в чат; дальше действуете вы, например через удалённый рабочий стол с телефона (Chrome Remote Desktop, RustDesk или Tailscale с RDP).

## 11. Что остаётся в планах

- Второе устройство (issue #4) и проверка скилла в новом чате (issue #14) требуют вашего участия.
- Windows 10: бесплатные обновления закончились, Windows 11 на этом железе не поддерживается; Bridge от этого не зависит.
- Отправка от вашего имени не отслеживается Bridge, только скиллом.
