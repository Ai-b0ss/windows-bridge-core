# Восстановление повреждённого GitHub outbox

Резервирование `comment_id` в `active` передаётся worker или publisher только
после успешной постановки задания в очередь. Любая ошибка чтения, карантина,
записи или передачи в очередь освобождает резервирование. Ошибка остаётся
видимой через `last_error`; следующий опрос может повторить восстановление.

## Сохранение результата и доказательств

- Проверяются схема, структура, числовой ID комментария, `node_id`, устройство,
  полный task, статус и исход. Для больших результатов проверяется также
  компактный task с хешем аргументов. Повторяющиеся JSON-ключи запрещены.
- Валидный сохранённый результат публикуется с прежним телом. Уже опубликованный
  результат только завершает локальную очистку pending request.
- Повреждённый файл копируется в `outbox/quarantine/`: исходные байты `.bin` и
  метаданные `.json` с ID, именем источника и SHA-256. До надёжной записи замены
  исходный файл остаётся на месте. Прерывание не превращает его в отсутствие
  результата и разрешение на новое исполнение.
- Учитывается также оставшийся после прерывания `<comment_id>.tmp`. При наличии
  обоих файлов приоритет имеет подтверждённый `.json`; `.tmp` сохраняется в
  карантине. Валидный одиночный `.tmp` становится сохранённым результатом.
- Если файл нельзя прочитать или сохранить доказательства, исходник не
  заменяется. Ошибка освобождает `active`, но не разрешает исполнение мутации.

## Контракт повторов

Для операций из существующего точного списка read-only допустимо повторить
тот же task. Pending request сохраняется до передачи worker, поэтому ошибка
публикации остаётся восстанавливаемой после перезапуска.

Для мутаций восстановление не вызывает RPC и не захватывает новое задание
журнала. Используется только ответ `done` с совпадающим digest. Ошибка исходной
операции остаётся той же ошибкой. Конфликт возвращает `TASK_ID_PAYLOAD_CONFLICT`,
истёкший ответ — `TASK_OUTCOME_EXPIRED`. Отсутствующая запись и остальные
состояния, включая `retryable`, дают `TASK_OUTCOME_UNKNOWN` с `retry_safe=false`:
наличие повреждённого outbox не позволяет доказать отсутствие прежнего эффекта.
Ошибки чтения или структуры журнала сохраняют исходный outbox для восстановления.

Ошибка доставки результата повторяет прежнее тело комментария, а не операцию
на компьютере. Неизвестный исход требует сверки эффекта и журнала оператором;
автоматическая выдача нового task ID для такой мутации недопустима.

Проверки выполняются на изолированных fixtures: локальный HTTP RPC, SQLite,
конкурирующие submit, повреждения файлов и сбои публикации. Это не проверка
реального GitHub inbox или установленного Bridge. Политика бесконечных сетевых
повторов, выбор устройства и Stop не меняются.
