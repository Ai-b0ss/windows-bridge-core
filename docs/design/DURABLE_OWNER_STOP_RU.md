# WB-REV-03 / PR-A1: сохраняемый Stop владельца

Stop имеет приоритет над разрешением из чата и над подписанным разрешением на
действие. До Stop сохраняется прежний локально включаемый режим согласия из чата.
После Stop новая цитата, другой агент, другая задача, смена режима и перезапуск
процесса не восстанавливают доступ.

## Реализация и граница доверия

Маркер `state/chat-permission/stop.flag` больше не удаляется при выдаче разрешения
или обработке отказа. Содержимое не интерпретируется: даже пустой файл, каталог
или ссылка означают Stop; ошибка доступа также блокирует действие. Только
отсутствие маркера разрешает продолжить обычную проверку полномочий.

Проверки стоят в `ChatPermissionPolicy`, выдаче и расходовании `AuthorityStore`,
`DesktopModes`, обёртке `guard_effect` и точках отправки физического действия.
При чтении режима после Stop сохранённые desktop grants очищаются с увеличением
generation. Старые grants блокируются и до этой очистки. Маркер остаётся на диске.
`chat_permission_status.owner_stopped` сообщает состояние блокировки.

Stop повторно проверяется после журналирования/выдачи разрешения, перед
диспетчеризацией, после запуска или ожидания Windows-MCP worker, перед событиями
встроенной физической последовательности и перед запуском видимого приложения.
Ожидающие input lease отменяются существующей проверкой состояния.

Это не транзакция между файловой системой и Windows: Stop, записанный после
последней проверки, не может отменить уже переданное событие ОС или внешний
Windows-MCP вызов. Уже запущенный внешний вызов может завершиться; новая попытка
блокируется. Автоматического повтора нет. Прерывание каждого события внутри
стороннего Windows-MCP здесь не реализовано.

Bridge остаётся программой текущего пользователя, а не песочницей для
произвольного кода этого пользователя. Администратор или уже запущенная программа
с правами записи в state могут менять файлы напрямую. PR закрывает обход через
протокол разрешений и связанные точки исполнения; защиту state средствами ОС
и остановку всех ранее запущенных фоновых процессов он не заявляет.

## Rearm: закрыто до доверенного локального восстановления

В этой версии нет RPC, строки в чате, переменной окружения или метода
`clear_stop`, снимающего Stop. Подписанное разрешение на действие тоже не rearm.
Протокол `ChatConsentBroker` проверяет nonce, подпись, устройство, запрос и
одноразовость для действия, но не связывает rearm с конкретным нажатием Stop.
Рабочий доверенный host issuer для такого восстановления пока не подключён.
Добавлять видимость доверия через агентский `approved=true` недопустимо.

**Ограничение UX:** удалённого безопасного возобновления после Stop пока нет.
Нельзя просить агента удалить маркер через shell, файловый RPC или новую цитату.
Если доверенное обслуживание недоступно, Bridge должен оставаться остановленным.

Доверенный владелец/контроллер может восстановить работу только локально, вне
агентского RPC, в окне обслуживания без работающих Bridge, input workers,
старых запросов и автоматического перезапуска на время изменения состояния:

1. Сохранить приватную резервную копию состояния локально, не в публичном Git.
   Убедиться, что прежние клиенты и фоновые действия завершены.
2. Очистить desktop grants с увеличением существующей generation. Не удалять
   файл режима с обнулением счётчика: старое поколение не должно стать новым.
3. Отозвать все ранее выданные authority grants с сохранением записей об отзыве
   и расходовании; не удалять базу approvals и базу challenges для «сброса».
4. Если был настроен подписывающий контроллер, заменить доверенный public key
   совместно с ним. Иначе ещё не импортированное старое подписанное разрешение
   может вновь попасть в Bridge. Без возможности исключить такие receipts
   восстановление не выполнять. Приватный ключ в Bridge не переносить.
5. Только после этого явно снять маркер Stop как последнее локальное действие,
   возобновить запуск и проверить отсутствие старых grants. Для дальнейшей работы
   выдать новое разрешение с новым поколением и точными целевыми окнами.

Это процедура для доверенного обслуживания, не готовый автоматизированный UX.
Она не выполняется данным PR. Будущий rearm должен иметь отдельную операцию,
доверенную подпись, nonce конкретного Stop, одноразовое расходование и защиту от
гонки с новым Stop; обычный подписанный action receipt использовать нельзя.

## Проверка и откат

Регрессия до исправления: в изолированном tempfile новая цитата успешно удаляла
Stop вместо ожидаемого `OWNER_STOPPED`. Новые тесты проверяют постоянство маркера,
другие agent/task, перезапуск состояния, старые разрешения, отказ до побочного
эффекта, гонки с выдачей, отправку worker и обычное разрешение до Stop.
Существующие RSA-тесты проверяют подпись, подмену и replay; дополнительно
проверяется, что корректный подписанный action receipt не снимает Stop.
Изолированный RPC smoke использует отдельный loopback процесс и временное
состояние, проверяет отказы и настоящий перезапуск только этого процесса.
Видимый ввод, кнопка на реальном desktop и live runtime здесь не проверяются.

Откат исходников — revert коммита PR и пересчёт release manifest по Git-байтам.
Откат возвращает уязвимое поведение: сохранённый `stop.flag` старый код может
удалить при новой цитате. Поэтому откат с возобновлением агентского доступа
недопустим; до исправления оставить Bridge недоступным для агентских действий.
Не восстанавливать старые grants из резервной копии и не удалять Stop ради отката.
Развёртывание и откат работающего runtime в этот PR не входят.
