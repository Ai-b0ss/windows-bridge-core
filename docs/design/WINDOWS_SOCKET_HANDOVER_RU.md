# Переключение Windows Bridge без потери соединений

Проблема: два независимо созданных Windows TCP listener на одном адресе/порту
с SO_REUSEADDR не обеспечивают атомарное переключение. Закрытие первого
listener способно сбрасывать уже поставленные в очередь соединения (WinError
10054), особенно под нагрузкой Windows Server. Простой повтор RPC опасен,
потому что неизвестно, применил ли сервер изменяющее действие до сброса.

## Новый протокол

1. A продолжает обслуживать 127.0.0.1:port.
2. B запускается с --standby --also-listen <check-port>. Его публичный
   сокет НЕ привязан; аутентифицированный check-port доступен.
3. A проверяет на приватном порту B режим standby, поддержку нового протокола
   и уникальность PID. А поднимает приватный RPC и записывает адрес для
   перенаправления запросов к своим старым сессиям.
4. A вызывает socket.share(B_PID); передаёт WinSock-данные на check-port
   B под общим секретом и с идентификатором процесса источника.
5. B проверяет создание сокета, адрес 127.0.0.1:port, тип TCP и режим listen,
   после чего принимает уже существующий listening socket через socket.fromshare.
6. A перестаёт принимать новые соединения. Его закрытие не уничтожает очередь
   сокета: дубликат остаётся открытым в B.
7. Старые сессии остаются у A и читаются через ранее существовавшее
   перенаправление, пока A не завершит работу.

## Безопасность и совместимость

- Операция adopt_listener допускается только через check-port, с общим RPC
  секретом. На публичном порту она отклоняется.
- Источник идентифицируется PID и токеном создания процесса; ошибочные
  данные WinSock не активируют слушатель.
- Старый A, не поддерживающий socket_handover_v1, НЕ СОВМЕСТИМ с новым
  standby B: оператор обновления должен проверить capabilities обоих до
  запуска протокола. Для старых установок необходим отдельный утверждённый
  сценарий с остановкой и запуском (допускающий краткий простой), а не
  слепое выполнение drain.
- На не-Windows протокол не запускается.
- Прямое обновление работающего Bridge и работа с личными сессиями требуют
  отдельно согласованного плана миграции и резервной копии. Этот PR
  проверяется только на временных экземплярах.
