# Восстановление CDP после исчезновения Chrome Default

Проблема: при перезапуске Windows Chrome Default может отсутствовать, тогда как DevToolsActivePort сохраняет прежний номер порта. Hub сообщает OWNER_CHROME_CDP_CONNECTION_REFUSED. Ранее установленный обработчик подтверждения умеет принимать диалог Chrome, но не запускать Chrome.

## Механизм

- tools/chrome_owner_autorecover.py: самостоятельная локальная задача Windows, без других агентов и вызовов ChatGPT. Использует только авторизованный Chrome Default. Для продолжения требует devtools.remote_debugging.user-enabled=true в локальном состоянии Chrome. Этот параметр самостоятельно не включает.
- Если Chrome уже запущен, не перезапускает и не закрывает его, не трогает иные профили и процессы Playwright.
- Если Chrome отсутствует, использует --no-startup-window --keep-alive-for-test --profile-directory=Default. --keep-alive-for-test — тестовый параметр Chromium, его поддержка после обновлений не гарантируется. Проверяется фактический PID и действующий слушатель CDP, а не только команда запуска.
- При ожидающем согласовании Chrome и отсутствии пользовательских окон создаётся временное служебное окно chrome://inspect/#remote-debugging. Оно позволяет уже разрешённому владельцем Chrome Consent Watcher обработать нативный запрос. Затем временное окно закрывается по проверенному PID и HWND, пользовательские вкладки не затрагиваются. При создании такое окно может кратковременно появиться или изменить фокус: строгая невидимость восстановления не гарантируется.
- Максимум 3 временных окна за 15 минут; пауза между попытками не менее 65 секунд; ожидание согласования не более 55 секунд. Отказ и ошибки не приводят к автоматической выдаче грантов или отключению защиты.
- Требуется интерактивный сеанс Windows, работа на заблокированном экране отдельно не подтверждена.

## Испытания

1. На реальном Chrome Default запуск без видимого окна восстановил процесс PID 10004 и слушателя 127.0.0.1:9222.
2. Служебное окно позволило Chrome Consent Watcher обработать диалог. В журнале: CDP_DIALOG_APPROVED hub=2988 chrome=10004. Reconnect worker подтвердил connected=true. Служебное окно затем было закрыто; Hub сохранил соединение и keepalive.
3. 7/7 изолированных тестов нового Python-модуля прошли, включая ограничения по чужим окнам, портам, отсутствию согласия, количеству попыток и точному закрытию окна.
4. При установке задачи Windows нужна новая проверка после потери процесса Chrome, включая очистку ресурса и отсутствие изменений активного окна по окончании.

## Автозапуск

Задача планировщика: FF-OwnerChrome-CDP-Supervisor, запуск при входе владельца в Windows, только в интерактивном сеансе.
Python: C:/Users/user/AppData/Local/Programs/Python/Python313/python.exe
Скрипт: K:/FF-Windows-Bridge/state/chrome-cdp-consent-watcher/chrome_owner_autorecover.py
Аргументы: --hub-state K:/FF-Windows-Bridge/state/hub --workdir K:/FF-Windows-Bridge/state/chrome-cdp-consent-watcher --interval 15

Отключение: Stop-ScheduledTask и Disable-ScheduledTask для FF-OwnerChrome-CDP-Supervisor.
Безопасная диагностика без вмешательств: --dry-run.
