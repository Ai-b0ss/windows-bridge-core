# API & deployment contract

Inspect capabilities from the live connected Bridge; no static README proves current support.

- Device identity: `device_status`, `device_ping`, `bridge_capabilities`, `bridge_call(op="device_info", args={})`.
- Unified no-effect task investigation (newer source/runtime only): `bridge_call(op="computer_use",args={"command":"task_preflight","app":"cursor","task":"<actual task>"})`. Returns programmatic candidates, task compatibility (not guaranteed success), optional existing-surface route preflight, and explicit next steps. Never launches a model or buys an API call.
- Opt-in vendor CLI contract probe on newer runtimes: `computer_use({"command":"task_preflight","app":"Cursor","task":"<actual task>","verify_cli_contract":true,"include_auth_status":true})`. Only pinned official install-location CLI help/version/status, never model prompt. Returns sanitized booleans and `quota_and_pricing_verified=false`; see [vendor contract audit](../../../docs/design/P0_VENDOR_CLI_CONTRACTS.md).
- Older runtime fallback: `bridge_call(op="computer_use",args={"command":"programmatic_plan","app":"cursor","task":"<actual task>","probe_versions":false})`. Candidate discovery alone is not real task verification.
- Exact action plan on a registered surface (newer runtime only): `computer_use({"command":"plan_action","surface_id":"<id>","operation":"<op>","policy":{"background_required":true}})`. This NEVER executes an action.
- Existing route executor: `computer_use({"command":"act","surface_id":"<id>","operation":"<op>","action_args":{},"postcondition":{},"policy":{"background_required":true}})` only after task suitability evidence; use the live contract for required arguments.
- Owner chat permission (target model, check `capabilities.features.owner_chat_permission.enabled`): `set_desktop_mode` with `mode:"dedicated"`, `agent_id`, `task_id`, `targets:[{"hwnd":N}]` (N from `gui_list_windows`; the Bridge resolves and verifies the window) and `owner_chat_permission:{quote,apps,duration_seconds}`; then `computer_use({"command":"windows_mcp","tool":"Click|Type|Scroll|Move|Shortcut|Clipboard|MultiSelect|MultiEdit|Wait","arguments":{},"agent_id","task_id","mode_generation"})`. Grants are independent per agent/task and per window; add `target_hwnd` to a physical `windows_mcp` call to work in one of your granted windows, and `lease_wait_seconds` (0-60) to bound queueing for the shared mouse/keyboard. `desktop_mode_status {agent_id,task_id}` lists all grants and current leases. Read-only reports: `chat_permission_status`, `scope_report`.
- Evidence/recovery: `durable_call`, `request_status`, and relevant owner-scoped session APIs if advertised by the connected Bridge.

The `computer_use` payload uses `command`, not an arbitrary `action` key. The public GitHub source, portable ZIP, installed file and active process are distinct objects; use `tools/runtime_inventory.py`. Never hard-code a user's hostname, port, secret path or GitHub issue into a publicly distributed skill.

Read-only discovery even without standalone Skill installation: `bridge_call(op="agent_workflows",args={})` exposes the recommended task lifecycle; capabilities also contains `agent_workflows`. This is static advice, never authentication or authorization. See [agent discovery](../../../docs/design/P0_AGENT_WORKFLOW_DISCOVERY.md).

Shared Hub browser & Agent Entry (preferred when the live capability is enabled): check `capabilities.features.universal_agent_runtime.enabled`; do not infer availability from this document or a release package. Use `bridge_call(op="hub",args={"op":"capabilities","args":{}})` (or `ff-universal-hub` MCP / `/agent/v1` scoped entry) and `route_plan {"surface":"browser","capability":"owner_profile_hidden"}` for the live contract. For no-interruption read-only reading of a specific `http(s)` URL using only already authorized and connected supported providers, use `route_plan {"surface":"browser","capability":"background_tab_read","url":"...","visibility":"background_tab|strict_invisible"}` and `site_read` (or local CLI `ff_hub.py site-read`): distinguishes ordinary background tabs from strict invisibility (never substitutes a visible tab for strict invisibility), reports ONE actionable capability result (`NO_ELIGIBLE_NO_INTERRUPTION_PROVIDER`) before any UI or pending request when no provider is eligible, and never advertises FF Browser Companion `0.1.1` (`downloads` + `nativeMessaging` only) as a page reader. For background form workflows on already authorized owned tabs without foreground interaction or policy changes, plan with `route_plan {"surface":"browser","capability":"background_tab_form","url":"...","visibility":"background_tab|strict_invisible"}` and drive owned tabs through normal Hub APIs (`owner_chrome_hidden` or `browser`: `open`, `observe`/`snapshot`, `act` supporting `fill|click|select|check|uncheck|press`, `wait_for`, keyed `reload`, `read`, `close`) with a stable `request_key` on every mutation to prevent duplicate submission (reconcile ambiguous replies via `request_status`; live host drift fails closed with `TAB_HOST_CHANGED`). Primary owner-auth browser automation uses **`owner_chrome_hidden` (`owner_chrome_profile1_hidden_secondary`)** — Chrome >=158 browser-level loopback CDP `Target.createTarget({hidden:true})` inside the already-running owner Chrome `selected active Chrome profile (e.g. Default or Profile N)` (inherits auth, zero cookie copy, zero visible HWNDs/taskbar/tab-strip side effects, requires `owner_chrome_hidden_secondary` grant + `selected active Chrome profile (e.g. Default or Profile N)` default context + loopback CDP; `screenshot` unsupported; fails closed if unavailable without substituting isolated mode or launching a 2nd Chrome process). **Optional isolated mode** (`managed_browser` / `private_browser`, optional isolated `profile_id`) is an explicit separate mode for non-owner-auth tasks only. Hub `browser` (`owner_chrome_extension`) is explicit-only visible-tab extension mode (`hidden_secondary_window_supported=false, visible_tab_strip=true`). Open one `session_open {agent_id,task_id}` session per task; pass `session_id`, `session_secret`, and a stable `request_key` for every mutation. On every exit path call `session_close` (with a stable `request_key`) in `finally`; verify `cleanup_verified=true`, `resources_retained=0`, and `owner_chrome_hidden_targets_closed` / `browser_tabs_closed`. Never silently fall back to direct visible Playwright or enable/restart production to probe a feature. See [scope and verification](../../../docs/UNIVERSAL_AGENT_RUNTIME_RU.md).

**Profile-directory bootstrap:** `hub.route_plan({surface:"browser",capability:"owner_profile_hidden"})` reports the actual `profile_dir_name` for the legacy-named `owner_chrome_profile1_hidden_secondary` route. `Default` and `Profile 1` are different Chrome directories. Use the live directory, check `state=READY` and local Hub grant, and report Chrome CDP approval separately. Keep session credentials private and never substitute another profile.
