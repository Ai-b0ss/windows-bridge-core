# Автовосстановление prelogin-сетевого процесса

Это необязательный компонент восстановления сетевого процесса Windows Bridge. Здесь хранится проверенный исходник supervisor, но **не** приватные VPN-профили, адреса, токены или журналы.

## Причина сбоя

При загрузке Windows локальный сетевой модуль мог завершиться с `Core connect timeout`: прежняя программа ожидала IPC-соединение с FlClashCore только 10 секунд. Хотя задача Windows имела настройки повторного запуска, в наблюдаемом случае они фактически не восстановили процесс. Отдельный Cloudflare Keeper продолжал работать, но ждал `state.json.phase === "Ready"` и не мог запустить агент.

## Исправление

- `supervisor.mjs` запускает доверенный соседний `prelogin-network-worker.mjs` и повторяет запуск при завершении процесса.
- Интервалы повторов: 3, 6, 12, 24, 48, затем максимум 60 секунд. После двух минут стабильной работы счётчик задержки сбрасывается.
- Состояние сохраняется в `prelogin-network/state.json`, журнал — в `prelogin-network/supervisor.log`.
- Supervisor не меняет VPN-маршруты и не перезапускает основное RPC-ядро.

## Интеграция

1. Сохранить исходную точку входа `prelogin-network.mjs` и экспортировать XML задачи `FF-CF-Prelogin-Network` для отката.
2. Разместить копию `supervisor.mjs` как `prelogin-network-supervisor.mjs` рядом с доверенным локальным `prelogin-network-worker.mjs`.
3. В приватном worker увеличить первоначальное ожидание IPC-подключения с 10000 до **45000 мс**. Полный исходник этого worker здесь намеренно не публикуется: он связан с машинными настройками.
4. Установить у прежней точки входа `prelogin-network.mjs` содержимое: `import './prelogin-network-supervisor.mjs';`.
5. Сохранить отдельные задачи планировщика: boot-trigger `FF-CF-Prelogin-Network` и Cloudflare Keeper. Настройки повтора самой задачи оставлять как резервный уровень.
6. Проверить синтаксис, изолированный тест и затем провести контролируемую проверку на реальном запуске Windows.

## Тестирование

`node --check tools/prelogin-recovery/supervisor.mjs`

`node --test tools/prelogin-recovery/test-supervisor.mjs`

Тест симулирует `Core connect timeout` на первой попытке, проверяет повторный запуск, переход в `Ready` и дальнейшее наблюдение. При локальном исправлении тест в изоляции прошёл. Полноценная приёмка после перезагрузки домашнего ПК **ещё не проводилась**.

## Безопасность и поставка

Модуль не включён в стандартный portable ZIP, не настраивает удалённый доступ и не запускается автоматически на чужих компьютерах. Локальную конфигурацию транспорта и закрытые секреты нельзя публиковать в этом репозитории. Для отката нужно вернуть исходную точку входа и перезапустить только соответствующую задачу в согласованное окно.
